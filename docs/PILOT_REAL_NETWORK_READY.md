## Постоянный QR для ПК

Для `Pilot PC #01` создан постоянный непрозрачный QR: он не содержит `external_pc_id` и его нельзя угадать по номеру ПК.

Откройте и распечатайте: [QR оплаты Pilot PC #01](https://clubpay.justix.uz/qr/pc_9fa6a7d6ec327a8242fed53307b021b8d67593f9cf3664563e5d09d539801b94).

Этот QR клеится у ПК. Он используется для начала сессии и, когда ПК корректно отмечен как `sleeping`, для сценария Wake-on-LAN. QR продления другой: временный, появляется только на экране активной сессии.

## Доступ в админку

Пилот создан от имени superadmin. Для коллеги нужен отдельный пользователь с ролью owner/admin именно в `Pilot — Real Network` через «Настройки → Доступы».

Не создавайте учётную запись с общими паролями. Для выдачи доступа нужны имя, рабочий email/телефон коллеги и выбранный им пароль. До этого пилотом может управлять superadmin через веб-админку.

Если кнопка создания пользователя не открывает форму из-за блокировщика всплывающих окон, используйте прямую ссылку: [добавить пользователя пилота](https://clubpay.justix.uz/settings/pcs?new-user=1). Этот fallback выкачен в production в коммите `21c7891`; после загрузки страницы форма должна оставаться открытой.

Пароль пользователя в этот документ не записывается: он передаётся владельцу отдельным безопасным каналом.

## Настройка тестового игрового ПК

1. Подключить ПК и Raspberry Pi к одной проводной сети клуба.
2. В BIOS включить Wake-on-LAN; в Windows разрешить пробуждение сетевой картой и отключить Fast Startup.
3. В админке открыть `Pilot — Real Network → Настройки → Компьютеры → Pilot PC #01 → Изменить` и указать фактический MAC-адрес сетевой карты ПК.
4. Установить на ПК ClubPay Agent Core и задать:
   - `external_pc_id`: `pilot-real-network-pc-001`;
   - production Core API/WSS;
   - отдельный Core token, выданный для пилота.
5. Установить Steam и нужные игры на сам игровой ПК. ClubPay не скачивает и не хранит игры: Agent показывает доступные локальные приложения и запускает их в kiosk-режиме.
6. Не использовать реальный Windows taskbar для игроков. Agent показывает только свой интерфейс; запущенные Steam/игры должны возвращаться через безопасную панель Agent.

## Raspberry Pi / Controller

1. Дать Raspberry Pi постоянный IP и подключение к той же LAN, что и игровой ПК.
2. Настроить Controller на production Core API, указать его отдельный Core token и идентификатор пилотного ПК `pilot-real-network-pc-001`.
3. Controller должен постоянно держать WSS-соединение с Core и уметь отправлять WoL magic packet на MAC игрового ПК.
4. Firewall/роутер не должны блокировать Controller доступ к API/WSS ClubPay по HTTPS/WSS (443).

## Как проверять MVP по порядку

1. Открыть постоянный QR с телефона на гостевом Wi-Fi: должна открыться страница именно `Pilot PC #01`.
2. Запустить сессию наличными из веб-админки: Agent должен получить `start_session`, показать таймер и QR продления.
3. Запустить Steam и игру: Windows/Explorer/taskbar не должны открываться пользователю; приложение должно быть доступно через Agent.
4. Отсканировать QR продления при активной сессии и в `FROZEN`: после оплаты/ваучера время должно прибавиться к этой же сессии.
5. Досрочно завершить сессию: проверить создание ваучера и его доставку в Telegram после привязки номера к `@clubPay_tg_bot`.
6. Выключить или перевести ПК в состояние сна, убедиться что Core видит его как `sleeping`, оплатить постоянный QR: Controller должен отправить WoL, ПК загрузиться, Agent переподключиться и сессия начаться.
7. Проверить гостевой Wi-Fi/Captive Portal: сеть изолирована от управляющей сети и игровых ПК; до авторизации разрешены только DNS/DHCP и ClubPay/платёжные домены.

## Что можно тестировать уже сейчас

Структура клуба, зона, ПК, тарифы и постоянный QR готовы. Через наличные, ваучеры и mock-оплату можно проверить основной flow без реальных списаний.

Для Payme/Click отдельно потребуются тестовые, а затем production merchant-ключи клуба. Для Wake-on-LAN нужны фактические MAC ПК, настроенный Raspberry Pi/Controller и BIOS/Windows-настройки — без них офлайн ПК корректно не принимает оплату.
