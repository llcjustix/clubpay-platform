# Первый вход: ручная проверка

## Сейчас: локальный OTP без Telegram

Откройте http://localhost:7357/ и обновите страницу. Должна появиться пометка
«Тестовый режим». Если её нет, запущена обычная
сборка; используйте команды ниже.

1. Введите тестовый номер `+998900000001` → **Продолжить**.
2. На следующем экране появится случайный шестизначный одноразовый код.
   Введите его в поле **Код для тестового входа** → **Войти**.
3. Откроется главная с вашим тестовым номером и пустым игровым временем.
   Баланс и имя автоматически не подставляются.
4. Перезагрузите страницу: вход должен сохраниться.
5. Откройте **Профиль**: номер, RU/UZ, выход из аккаунта.
6. Нажмите **Выйти из аккаунта**: снова экран телефона. После перезагрузки
   профиль также не должен открываться без нового OTP.

Для проверки ошибок введите другой шестизначный код: вход будет отклонён.
Код действует 3 минуты и работает один раз; после 5 неверных попыток нужен
новый challenge. **Получить новый код** возвращает к вводу номера: нажмите
**Продолжить** ещё раз. Лимиты сохранены: 3 запроса на номер, 5 на устройство
за 15 минут. Не используйте один номер для бесконечных повторов подряд.

Это проверка Flutter → HTTP → PostgreSQL → access/refresh → хранилище браузера.
Отправка контакта и доставка сообщения Telegram имитируются. Она **не проверяет
владение номером**, настоящий Telegram или доступ к production-профилю.
OTP виден только в ответе локального тестового сервера и на экране; сервер
не печатает коды и токены в логи. В БД сохраняется хэш кода.

Стандартные migrations создают demo-каталог, но профиль нового игрока пуст.
Этот стенд предназначен для первого входа и навигации; реальные оплаты и запуск физических компьютеров здесь не подключены.
Если QR отсутствует в тестовой БД, стенд проверяет его на фиксированном рабочем
API без передачи токенов. Рабочий ПК и тарифы показываются с отметкой
«Рабочий ПК · просмотр», без оплаты и без подстановки тестового баланса.
Ошибка рабочего API (например 502) показывается как недоступность сервера,
а не как истечение QR. «Повторить проверку» повторяет тот же код.

## Повторный запуск

Нужна отдельная локальная PostgreSQL БД `clubpay_mobile_test`. На подготовленном
Mac она работает на `127.0.0.1:55439`, пользователь — текущий macOS user.
После перезагрузки Mac кластер можно поднять командой:

```sh
pg_ctl -D /tmp/clubpay-mobile-pg/data \
  -l /tmp/clubpay-mobile-pg/postgres.log start
```

Если каталог в `/tmp` удалён, создайте новую disposable БД с этим именем;
не подставляйте рабочую БД. Harness дополнительно проверяет loopback host,
имя БД и использует отдельную схему `mobile_browser_sandbox`.

Терминал 1, из корня репозитория (порт 8088 должен быть свободен):

```sh
CLUBPAY_BROWSER_SANDBOX=1 \
MOBILE_TEST_DATABASE_URL="postgres://$(id -un)@127.0.0.1:55439/clubpay_mobile_test?sslmode=disable" \
go test -tags mobiledev ./internal/httpapi \
  -run '^TestMobileBrowserSandbox$' -count=1 -timeout=0 -v
```

Терминал 2, из корня репозитория:

```sh
cd mobile/clubpay_client
flutter run -d chrome --web-port=7357 --web-hostname=localhost \
  --dart-define=API_BASE_URL=http://localhost:8088 \
  --dart-define=LOCAL_OTP_TEST_MODE=true
```

Для остановки — Ctrl+C в обоих терминалах. Harness расположен в
`internal/httpapi/mobile_dev_test.go` с build tag `mobiledev`: ни обычный
`go run ./cmd/api`, ни production-сборка не включают эту имитацию. UI-коды
показываются только при явном флаге, debug-сборке и loopback API.

## Настоящий OTP через Telegram

Нужен отдельный тестовый бот с backend-конфигурацией `TELEGRAM_BOT_TOKEN` и
`TELEGRAM_BOT_USERNAME`. Запускайте обычный `cmd/api` с другой тестовой БД
и `TELEGRAM_POLLING_ENABLED=true`; у этого бота не должно быть действующего
webhook или другого polling-процесса. Flutter запускайте без
`LOCAL_OTP_TEST_MODE`. Секрет бота не передаётся Flutter.

Сценарий: **номер → Продолжить → Открыть Telegram → Start → отправить свой
контакт кнопкой бота → получить OTP → вернуться в приложение → ввести OTP →
главная**. Номер контакта должен совпадать с введённым. Чужой контакт,
неверный/истёкший OTP не должны давать вход. Затем повторите проверку
перезагрузки и выхода из пунктов 4–6.

Без токена и доставки updates этот сценарий пока недоступен: локальная
имитация не является подтверждением работы настоящего Telegram.
